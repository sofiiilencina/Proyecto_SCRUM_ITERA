Fundamentos de la Calidad

La calidad del software trasciende la simple ausencia de errores; representa el grado en que un conjunto de características inherentes a un sistema cumple con las necesidades y expectativas tanto explícitas como implícitas de los usuarios y partes interesadas. Involucra el cumplimiento estricto de las especificaciones funcionales, combinado armónicamente con atributos esenciales de calidad interna y externa como la fiabilidad, la eficiencia operativa, la mantenibilidad del código, la usabilidad de la interfaz y la seguridad de la información.

Etapas de la calidad

✓

Control de calidad

Inspección al 100% del producto final. Elevados costes de inspección, baja participación, departamento separado del de producción.

☰

Aseguramiento de calidad

Implantación de un sistema de gestión de calidad, con ideas de calidad extendidas a toda la empresa. La calidad como ventaja competitiva.

★

Calidad total

Búsqueda de alto nivel de calidad con mejora continua y permanente, donde participan todos los departamentos, figura de cliente interno y externo, olaboración del proveedor y autocontrol del personal.

◎

Excelencia empresarial

Buscar la satisfacción del cliente y la eficiencia económica en todas las fases de la calidad, utilizando modelos aceptados y eficaces.

Métricas de calidad

Son indicadores cuantitativos y objetivos utilizados por los equipos de ingeniería para evaluar la eficacia de los procesos de desarrollo y a excelencia del producto final. Permiten medir y monitorear aspectos clave como la densidad de errores (defectos por mil líneas de código), el volumen de código defectuoso o redundante, el porcentaje de cobertura de pruebas unitarias y el esfuerzo medio requerido para la corrección de incidencias (MTTR - Mean Time To Repair).

Técnicas de Aseguramiento de la Calidad

Las pruebas de software buscan defectos antes de que lleguen al usuario. Tóca una tarjeta para ver el detalle.

Niveles de prueba

▣

Pruebas Unitarias (Unit Testing)

Primer nivel de verificación en la pirámide de pruebas. Evalúan de manera aislada componentes mínimos del sistema (funciones, métodos o clases) para comprobar que la lógica interna funcione exactamente como fue diseñada.

Se ejecutan sin depender de la base de datos, servicios externos u otros componentes, utilizando dobles de prueba cuando es necesario.

⇄

Pruebas de Integración (Integration Testing)

Evalúan la interacción, la interfaz lógica y la transferencia de datos entre módulos o servicios previamente probados por separado.

Su objetivo es detectar fallos en la comunicación entre componentes internos, servicios web externos, bases de datos o APIs de terceros.

☰

Pruebas de Sistema (System Testing)

Validan la plataforma de software completa, ensamblada e integrada en un entorno similar al de producción.

Verifican el cumplimiento global de los requerimientos, abarcando aspectos funcionales (flujos de trabajo) y no funcionales (rendimiento, carga, seguridad).

Tipos de prueba

■

Caja Negra (Black-Box Testing)

Estrategia enfocada en verificar las entradas enviadas al sistema y analizar las salidas obtenidas frente a las especificaciones esperadas.

El evaluador ignora la estructura interna del código y se centra en el comportamiento funcional externo desde la perspectiva del usuario.

□

Caja Blanca (White-Box Testing)

Examina la estructura interna, la arquitectura lógica y la implementación del código fuente.

Requiere habilidades de programación para diseñar casos que garanticen la cobertura de caminos lógicos, bucles, bifurcaciones y manejo de excepciones.

Herramientas de Calidad

Las herramientas de calidad permiten facilitar y organizar distintas actividades relacionadas con el desarrollo y la validación de software. Entre las principales se encuentran:

☰

Test Management

Herramientas destinadas a gestionar y organizar las actividades de prueba, incluyendo casos de prueba, ejecuciones, resultados y evidencias, permitiendo evaluar el comportamiento del sistema y detectar posibles problemas.

Gestión de pruebas
⚑

Bug Trackers

Herramientas utilizadas para registrar, organizar y gestionar errores o incidencias detectadas durante el desarrollo y las pruebas de testeo.

Seguimiento de defectos
✧

Linters

Herramientas que analizan el código fuente para identificar errores, inconsistencias y posibles incumplimientos de estándares o buenas prácticas que puedan afectar la calidad y mantenibilidad del software.

Análisis de calidad
✎

Seguimiento de Defectos

El seguimiento de defectos permite registrar y controlar los problemas encontrados durante el desarrollo y las pruebas del software. La información asociada a cada defecto puede incluir su descripción, prioridad, estado, responsable y evolución hasta su resolución. Los Bug Trackers son las principales herramientas utilizadas para esta actividad.

Seguimiento de defectos
▥

Análisis de Calidad

El análisis de calidad permite evaluar diferentes aspectos del software para identificar errores, inconsistencias y oportunidades de mejora. Su objetivo es detectar problemas de manera temprana y verificar el cumplimiento de estándares y buenas prácticas.
